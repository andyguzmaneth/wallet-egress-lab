What to change

10 changes cover all 786 address-linked requests; 5 add no latency

Safe already routes RPC through eRPC, so upstream providers see Safe's IP addresses, not users', and the cookie banner lets users decline analytics. The gaps: Safe's own services still receive the IP address with the Safe address, and Google Analytics receives addresses after analytics is declined.

Ship now No added latency

  1. Google Analytics receives the Safe and owner addresses, with analytics declined.
    Send nothing without consent; drop addresses from events and URLs. Consent mode was denied, so Google drops cookies but still receives ep.safeAddress, up.walletAddress and the page URL. The client ID changes on each page load; the address is what links the visits.
    105 address-linkedNo added latency
  2. Page loads send the Safe address to Safe's web host, in the URL or the Referer header.
    Keep the address out of URLs and set a strict Referrer-Policy. 0 requests carry ?safe= in the URL and 97 in the Referer header; the host and its CDN can log both.
    97 address-linkedNo added latency
  3. Sanctions checks send the Safe and owner addresses to Safe's mainnet RPC, even on Sepolia.
    Check against a local copy of the public list. The checks call the Chainalysis oracle with isSanctioned. The list is small and can be rebuilt from the oracle's events, so the check stays and the address stays on the device.
    12 address-linkedNo added latency
  4. The CoW widget's error reports to Sentry tag the Safe address.
    Strip addresses before a report leaves the browser. The address travels in a walletAddress tag and in request URLs.
    7 address-linkedNo added latencyCoW owns this
  5. WalletConnect reports a persistent client ID although it is not used.
    Load the SDK only when the user picks WalletConnect. Requests to pulse.walletconnect.org carry a did:key client ID from the first page load.
    1 address-linkedNo added latencyReown owns this

Opt-in privacy mode · anon-RPC: requests over Tor hide the IP address +0.9 to 3.2 s per call in the browser, plus startup (12 to 50 s when cold)

  1. Safe's backend sees the IP address with the Safe address, including transaction details before signing.
    Send backend calls through the anon-RPC transport (Tor). The idle app asks about the Safe every 15 s. Tor hides the IP address; Safe still sees which Safe, which owner and the pending transaction. The app page has to load over Tor too, or timing links the two.
    418 address-linked+0.9 to 3.2 s per call
  2. CoW's API sees the IP address with the Safe address, quotes and orders.
    Send CoW API calls through the same anon-RPC transport. Quotes, order submission, order tracking, notifications and the balance watcher all name the Safe.
    28 address-linked+0.9 to 3.2 s per callCoW owns this
  3. ENS reverse lookups send owner and recipient addresses to an RPC; 19 of 28 go to Safe's mainnet RPC during this Sepolia session.
    Resolve names over anon-RPC and cache the results. Names change rarely; a PIR name index can replace the lookup later.
    28 address-linked+0.9 to 3.2 s per call

Latency cost

anon-RPC in the browser adds an estimated 2 to 35 s per action

Each bar is the extra wait for one action when only its address-linked requests go over Tor, measured against the same journey on clearnet. This run used a native Tor client. Inside a web page Tor runs as tor-js, which is slower today: 0.9 to 3.2 s per request against 1.4 s here, plus startup time (12 to 50 s when cold, less when stored state is fresh).

Where we plan to cut the wait

These are first numbers from one network in one configuration. Most of the wait comes from requests that wait on each other, so the path and the request pattern both matter.

  • Fewer round trips. Batch the dependent reads into one request, and fetch them while the app is idle so an action does not wait on them.
  • A warm connection. Start Tor when the app loads and keep circuits open, so the startup cost never lands on a send or a swap.
  • Shorter paths. An onion service run by the provider removes the exit hop; circuit length and reuse are settings to test.
  • Other networks. Tor is one anonymity network. Mixnets such as Nym, and modes with different delay and cover-traffic settings, trade latency against protection differently. A swap can use a faster mode than background polling.

No mainnet pass in this run.

Chromium (Playwright, fresh profile, QUIC off) ran behind mitmproxy, so every request from the page, its iframes and its service worker was recorded with headers and bodies. The signer was an injected EIP-1193 provider whose keys and RPC stay outside the browser. A blank-page baseline run removed the browser's own traffic. Identifiers were found by searching URLs, headers and bodies for the Safe address, the owners, the counterparty, safeTxHash, CoW order ids and analytics client IDs. Cookie banner choice: necessary only. Each request gets the highest tier whose rule it matches:

  1. Address-free. No address or client ID; the receiver still sees the IP address, the time and what was fetched.1,091 requests
  2. Telemetry & fingerprint. A client or device ID, without an address.47 requests
  3. Address-linked read. The Safe address or an owner address, which the receiver links to the IP address.757 requests
  4. Transaction details before signing. What the user is about to do (recipient, amount, calldata, signature) before it is on chain.29 requests

Limits: one scripted run on Sepolia, fresh browser cache, necessary-only cookies. Not measured: the signer's own RPC and the broadcast of the signed transaction; over Tor, Cloudflare challenges and IP geofencing can block calls.
