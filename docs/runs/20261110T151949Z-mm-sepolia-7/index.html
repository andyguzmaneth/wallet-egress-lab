Findings

What leaves the extension by default

  1. Import queries every chain MetaMask supports. The import step alone sent 227 requests, 75 of them address-linked. MetaMask derives Bitcoin, Solana, Tron and Stellar accounts from the phrase by default and asks Infura's mainnet endpoints about them (Tron 75, Bitcoin 38, Stellar 26, Solana 11 address-linked requests over the run). Bitcoin is queried by script hash for the first receive and change addresses of each account.
  2. The profile service links all accounts of the phrase. Backup and sync is on by default. It signs in with a key derived from the phrase, then registers each account with the authentication API (2 PUT requests to /profile/accounts, one per account, each listing its EVM, Bitcoin, Solana, Tron and Stellar addresses with signed proofs, under the same MetaMetrics ID, so accounts A and B sit in one profile). 121 later requests carry the profile token. The rewards and notification APIs also receive the address lists.
  3. Declining usage data stops Segment, not the MetaMetrics ID. Segment received one event, "Metrics Opt Out", at the moment of the decline. The MetaMetrics ID then went to MetaMask's services in 3 requests.
  4. A custom RPC moves Sepolia reads only. After the custom Sepolia RPC was set, Sepolia reads went to it (13 address-linked) and 1 requests went to Infura Sepolia. In the same steps the MetaMask API still received 16 and Infura's non-EVM endpoints 12 address-linked requests.
  5. A third party outside Consensys gets the address by default. Hyperliquid's API received account A's address in 8 requests (perpetuals balance lookups). The user never opened Perps.
  6. The swap confirmation leaves before the user signs. MetaMask's confirmation screen sent 33 simulation requests and 5 security scans with the transaction to MetaMask's servers. It showed 2 alerts, which the run acknowledged: Unnecessary permission; High-risk request.

The MetaMask Chrome build 13.56.0 came from the MetaMask GitHub releases, checked against the release's SHA256SUMS and its Sigstore provenance. Chromium (Playwright, persistent profile, QUIC off) loaded it unpacked and ran behind mitmproxy, so every request from the extension pages, its service worker, its snaps and the swap page was recorded with headers and bodies. A blank-browser baseline removed Chromium's own traffic by host. With the extension installed and never opened, for 0 minutes, MetaMask sent 3 requests: accounts.api.cx.metamask.io/v2/supportedNetworks, chainid.network/chains.json. None carried an identifier.

Requests are attributed by their Origin or Referer header: an http(s) site is the dapp page; a chrome-extension:// origin, the "null" origin of MetaMask's sandboxed snaps, or none is MetaMask. Identifiers were found by searching URLs, headers and bodies for accounts A and B, contact R, the hashes of the run's transactions, and the Bitcoin, Solana, Tron and Stellar addresses (and Bitcoin script hashes) derived from the phrase with standard paths. All eight derived addresses appear in the capture. Each request gets the highest tier whose rule it matches:

  1. Address-free. No address or client ID; the receiver still sees the IP address, the time and what was fetched.346 requests
  2. Telemetry & fingerprint. A client, device or profile ID, without an address.106 requests
  3. Address-linked read. An account address (EVM or one of the derived Bitcoin, Solana, Tron and Stellar addresses), which the receiver links to the IP address.261 requests
  4. Transaction details before signing. What the user is about to do (recipient, amount, calldata) before it is on chain: simulation, security scan, broadcast.48 requests

Checks: analysis/verify_mm.py recounts the request and address-linked totals from the raw capture and matches the analysis exactly; ten address-linked requests were read raw and each carries the value, and ten address-free ones carry none. Shares are of requests, not bytes. All 16 steps completed.

Limits: one scripted run, fresh profile, Sepolia only. The multisig steps of the Safe journey have no MetaMask equivalent and were not run. MetaMask Swaps has no test networks, so the swap went through the CoW Swap page. Payload contents that MetaMask encrypts before upload (backup and sync data) were not decrypted.
