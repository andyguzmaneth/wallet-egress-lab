How we did it

A script played one user through {{NSTEPS}} actions on Sepolia: create a 2-of-2 Safe, receive ETH and WETH, send ETH through the multisig flow, swap WETH for COW in the CoW widget, sit idle, and switch to a custom RPC. A second, read-only pass opened a public Safe on mainnet. A recording proxy captured every request, and each request got a privacy tier.…

Chromium (Playwright, fresh profile, QUIC off) ran behind mitmproxy with a trusted CA, so every request from the page, its iframes and its service worker was recorded with headers and bodies. The signer was an injected EIP-1193 provider whose keys and RPC stay outside the browser, so the capture holds only traffic that Safe{Wallet} and its embedded widgets make. A blank-page baseline run identified the browser's own traffic, which is excluded. Identifiers were found by searching URLs, headers and bodies for the Safe address, the owners, the counterparty, safeTxHash, CoW order ids and analytics client IDs. Latency cost

{{LAT_T}}

For each user action, the table takes the address-linked requests in the first {{WINDOW}} s after the action, counts each endpoint once (repeated polls of the same endpoint are dropped), and finds the longest chain of them that run one after another. Parallel requests share one added delay; sequential requests add up. The estimate multiplies the chain length by the added latency per request: {{TOR}} s for Tor (p50 measured from an Arti client), {{OHTTP}} ms for one Oblivious HTTP relay hop (assumed). It is an upper bound for interactive steps, because some sequential requests do not depend on each other.

PIR balance lookup: {{PIR}} s p50 over clearnet, about 760 KB uploaded per lookup. OHTTP: {{OHTTP}} ms for one extra relay hop, an assumption, not a measurement.
