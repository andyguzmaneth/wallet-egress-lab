Latency cost of hiding the origin

For each user action, the table takes the address-linked requests in the first {{WINDOW}} s after the action, counts each endpoint once (repeated polls of the same endpoint are dropped), and finds the longest chain of them that run one after another. Parallel requests share one added delay; sequential requests add up. The estimate multiplies the chain length by the added latency per request: {{TOR}} s for Tor (p50 measured from an Arti client), {{OHTTP}} ms for one Oblivious HTTP relay hop (assumed). It is an upper bound for interactive steps, because some sequential requests do not depend on each other.

Method and limits

Chromium (Playwright, headed under Xvfb, fresh profile, QUIC off) ran behind mitmproxy with a trusted CA, so every HTTP request and WebSocket message from the page, its iframes and its service worker was recorded with bodies. The signer was an injected EIP-1193 provider whose keys and RPC stay outside the browser, so the capture holds only traffic that Safe{Wallet} and its embedded widgets make. A baseline run with a blank page identified the browser's own Google traffic, which is excluded. Identifiers were found by searching URLs, headers and bodies for values the harness knows: the Safe address, both owners, the counterparty, safeTxHash and CoW order ids, and analytics client IDs.{{FAILS}}

Latency references: direct RPC about 90 ms p50; Tor through an Arti client {{TOR}} s p50 and 7.3 s p95; tor-js in the browser {{TORJS}} s p50 per call after a 26 to 30 s bootstrap; a PIR balance lookup {{PIR}} s p50 over clearnet with about 760 KB uploaded per lookup. The OHTTP figure is an assumption for one extra relay hop, not a measurement.

Limits: one session per plan on one day; Sepolia hides some mainnet features, so a read-only mainnet pass on a public Safe was added; the mobile app and browser extensions were out of scope; the tier is a lower bound for requests whose bodies are compressed or binary.
