Main finding

The open wallet sends the address to 19 default chain RPCs once a minute

While the wallet UI is open, every 60 seconds it sends a balance multicall (aggregate3 with getEthBalance(address)) to the default RPC of 19 of its 20 active chains, and the address to its own portfolio API at walletchan.eth.sh. In 90 seconds of idle, {{IDLEN}} requests went out and all of them carried the address, to {{IDLEOPS}} operators. A user with funds on one chain tells 17 RPC operators (dRPC, Binance, Alchemy, Arbitrum, OP Labs, Avalanche, MegaETH, Robinhood, Monad, Berachain, Hyperliquid, Linea, Ink, Plasma, Unichain, ZKsync, Abstract) that the address is active, from the same IP, once a minute. Tempo, the 20th active chain, was not queried in this run.

What stays local or on the user's RPC

  • With a custom Sepolia RPC set, the whole send (gas estimate, eth_simulateV1, debug_traceCall, broadcast, receipt) went to that RPC. No request went to the default Sepolia RPC after the change.
  • The Shield screen and the Private tab made no new requests with no deposits.
  • The last 2 minutes produced one request, an ETH price with no identifier. The wallet had most likely auto-locked (default 15 minutes).
  • No analytics SDK, install ID or client-ID header was found other than WalletConnect's.
  • The block-explorer enhancement (on by default) sent only the transaction hash, to the user's RPC.

Settings

Onboarding shows no privacy choices. No setting turns off findings 1 to 9. Hiding chains reduces finding 1, and a custom RPC per chain moves finding 1 to the user's provider. Clear-signing descriptor lookups (contract address and selector, no user address) have a toggle, on by default.

Privacy policy and observed traffic

The policy (dated 2026-07-27) lists blockchain RPC endpoints, eth.sh (labels for contract addresses), Google Favicons and the Bankr API, and states that no analytics are collected. It does not list the walletchan.eth.sh portfolio, swap, domain-reputation and clear-signing endpoints, the WalletConnect telemetry, or CoinGecko. eth.sh received user counterparty addresses, not only contract addresses.

Default Sepolia RPC

The default Ethereum Sepolia RPC, sepolia.drpc.org, answers 400 chain is not available on free plan. Sepolia balances stay empty until the user adds a custom RPC; this run used ethereum-sepolia-rpc.publicnode.com.

Method

How this was recorded

  • Build: WalletChan v{{VERSION}}, walletchan-v4.2.0.zip from the project's GitHub releases, SHA-256 fb7ea57057e6333d915d25a1c3431acccf832fb77469785a39bfc72a820f6b55. The Chrome Web Store build is also 4.2.0, built separately, with the same set of hosts in its code.
  • Capture: mitmproxy and Playwright Chromium, fresh profile, a recovery phrase generated for this lab, Sepolia ETH only.
  • Journey: install, import the phrase, open the wallet, idle 90 s, enable Sepolia, set a custom Sepolia RPC, receive ETH and WETH from an outside account, Activity and Positions, import WETH, send 0.001 ETH between two lab accounts, request a Base ETH-to-USDC swap quote (not executed), open Shield and the Private tab, connect to MetaMask's test dapp, personal_sign, signTypedData_v4 (rejected), open vitalik.eth, open the transaction on Sepolia Etherscan, idle 2 min.
  • The steps were driven one at a time through the lab's control port, with a marker per step. There is no scripted driver for WalletChan yet, so this run cannot be repeated byte for byte.
  • A static read of the source (every endpoint, trigger and setting) was done alongside and cross-checked against the capture.
  • Not covered: swap and bridge execution, Shield deposit and withdrawal (mainnet only in the release build), Safe, Ledger, Bankr, WalletConnect sessions, long periods with the UI closed.

Checks

  • 10 random address-linked requests: the address is present in all 10.
  • 10 random address-free requests: none contains a lab address; the 40-hex values present are token and contract addresses.
  • Every host the source read lists for the steps run appears in the capture, except CoinGecko token pricing (testnet tokens) and the WalletConnect relay socket (no session opened).
  • The source read and the capture disagreed once: the source read concluded WalletConnect telemetry is off; the capture shows the telemetry event. This page follows the capture.
